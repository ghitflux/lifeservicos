# Incidente — API Indisponível (Login Falhou)

**Data**: 2026-04-07  
**Duração**: ~40 minutos (detectado e resolvido na mesma sessão)  
**Impacto**: Todos os usuários impossibilitados de logar na aplicação

---

## Sintoma

Usuários reportaram impossibilidade de login. A aplicação retornava erro sem
resposta (timeout).

---

## Causa Raiz

O container `src-api-1` ficou em estado `unhealthy` e **parou de responder
qualquer requisição** (HTTP 000 — timeout total).

**Erro nos logs da API:**
```
sqlalchemy.exc.InvalidRequestError: Select statement '<...>' returned no FROM
clauses due to auto-correlation; specify correlate(<tables>) to control
correlation manually.
```

Este erro em uma query SQLAlchemy bloqueou o event loop do Uvicorn, tornando
a API completamente irresponsiva. O health check confirmou:

```
Health check exceeded timeout (30s) [3x consecutivo]
```

**Agravante:** A restart policy dos containers estava configurada como `no`
(padrão Docker Compose sem `restart:`), então o container ficou `unhealthy`
indefinidamente sem reiniciar automaticamente.

---

## Solução Aplicada

### Imediata (restauração do serviço)
```bash
cd /opt/lifeservicos/src
docker compose restart api
```

Após reinício, a API voltou para `healthy` em ~2 minutos. Login funcionando.

### Protocolo de reinicialização automática (prevenção)

**1. Autoheal container** — monitora containers unhealthy e reinicia automaticamente:
```bash
docker run -d \
  --name autoheal \
  --restart=unless-stopped \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -e AUTOHEAL_CONTAINER_LABEL=all \
  -e AUTOHEAL_INTERVAL=30 \
  -e AUTOHEAL_START_PERIOD=60 \
  willfarrell/autoheal
```

**2. Restart policy** — atualizada em todos os containers sem reiniciá-los:
```bash
docker update --restart=unless-stopped src-api-1 src-web-1 src-db-1 src-proxy-1
```

**3. `docker-compose.yml` atualizado** com:
- `restart: unless-stopped` em db, api e web
- Healthcheck no db (`pg_isready`)
- Labels `autoheal=true` em api e web
- Serviço `autoheal` permanente

## Causa Técnica a Investigar

O erro SQLAlchemy `auto-correlation` foi disparado por alguma requisição ao
endpoint de rankings (alterado no deploy de 2026-03-18). Investigar qual
subquery está causando a auto-correlação e corrigir a query antes que volte
a ocorrer.

**Suspeita**: o uso de `or_()` combinado com subqueries em `rankings.py`
pode estar gerando auto-correlação em SQLAlchemy em cenários específicos de
filtragem.
